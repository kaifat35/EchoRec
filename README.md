# EchoRec

Минималистичное Android-приложение (Android 11+) для сохранения локальных AAC/M4A-записей с микрофона. Оно показывает амплитуду `MediaRecorder`, позволяет поставить запись на паузу, воспроизвести, удалить или отправить готовый файл и держит активную запись в foreground-сервисе.

## Важное ограничение Shizuku и VOICE_CALL

**Shizuku не делает обычное приложение системным приложением и не отменяет ограничения Android на `MediaRecorder.AudioSource.VOICE_CALL`.** Разрешение Shizuku даёт доступ только к Binder API процесса Shizuku. Для захвата потока собеседника на современных Android нужен отдельный, действительно привилегированный компонент захвата (например, user service, реализованный и запущенный через Shizuku, с доступом конкретной прошивки) либо системная/предустановленная OEM-программа. Простая подстановка `VOICE_CALL` в `MediaRecorder` процесса приложения не использует Shizuku и обычно завершится `SecurityException` или даст пустой поток.

Поэтому этот репозиторий намеренно использует надёжный `MIC` как fallback всегда и **не обещает запись собеседника**. Экран корректно обнаруживает Shizuku, слушает подключение/отключение, запрашивает его API-разрешение и явно сообщает пользователю об этом ограничении. Это безопаснее, чем ложная индикация «записи двух голосов».

## Сборка и запуск

1. Откройте корень проекта в Android Studio и дождитесь Gradle Sync.
2. Установите Android SDK, соответствующий `compileSdk`, указанному в `app/build.gradle.kts`.
3. Запустите конфигурацию `app` на устройстве с Android 11 или новее.
4. Предоставьте разрешение **Микрофон**; на Android 13+ также разрешите уведомления, чтобы видеть foreground-уведомление.
5. При необходимости установите и запустите Shizuku (ADB или Wireless debugging), затем нажмите «Разрешить» в карточке. Это проверяет API Shizuku, но не добавляет возможности захвата `VOICE_CALL` без упомянутого привилегированного сервиса.

## Архитектура

* `MainActivity` запрашивает runtime-разрешения и регистрирует Binder/permission callbacks Shizuku.
* `RecorderViewModel` создаёт `MediaRecorder` с `MPEG_4` + `AAC`, каждые 75 мс читает `maxAmplitude` для визуализатора, ведёт время с исключением пауз и загружает `.m4a` из `getExternalFilesDir(Music)`.
* `RecordingService` запускается только пока идёт запись; он публикует foreground-уведомление с типом `microphone`.
* Compose UI показывает состояние Shizuku, запись и список файлов. Для sharing используется `FileProvider`, поэтому путь к файлу не передаётся стороннему приложению напрямую.

## Жизненный цикл записи

После `prepare()` и `start()` создаётся файл. `pause()`/`resume()` доступны с Android N; ViewModel корректирует базовую временную отметку после паузы. `stop()` финализирует контейнер M4A; очень короткий/повреждённый файл удаляется. При исключениях освобождаются `MediaRecorder` и `MediaPlayer`, а пользователь получает Toast с причиной.
